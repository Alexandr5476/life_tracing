# RU/EN localization and appearance release matrix

S1 verifies the production string contract and adds representative Android resource checks. AppCompat owns app language. DataStore owns the four appearance preferences. Use the [design guide](../design/README.md) for visual criteria and the [implementation clarifications](../spec/lifetracing_implementation_clarifications.md) for historical timestamps and Plan scheduling.

## Configurations

Use a disposable Pixel 2 debug installation. Record the build SHA, API level, device and configuration ID. In Android Settings set the primary system language, Light/Dark mode, font size and display size. Set the app preferences through LifeTracing Settings.

| ID | App language / primary Android language | App theme / Android theme | Accent | App interface / text | Android font / display | API |
| --- | --- | --- | --- | --- | --- | --- |
| A | English / Russian | System / Light | Default | 100% / 100% | Default / default | 33 baseline |
| B | Russian / English | Dark / Light | Slate | 120% / 130% | Largest / one step above default | 33 stress |
| C | System / English → Russian | System / Light → Dark | Default | 100% / 100% | Default / default | 31 and 33 |
| D | English / English | Light / Dark | Slate | 90% / 90% | Default / default | 26 baseline and 33 |

Change language and theme separately in C. Open Settings and Archive before and after each change, rotate once, then leave and reopen the routes. On B, also background and resume from an actionable screen. Record app selections, selected date and whether focus returns to a surviving target. API 26/31 exercise the older AppCompat locale path. API 33 exercises framework app locales. Baseline smoke on API 35 and 36 remains part of wider release verification.

## Manual protocol

1. Start with an empty disposable installation. In Library create a timed Activity with a Number field, a No-live Activity and a two-step Sequence using those Templates. Use long names and a comment, for example “Tempo 42 — 30 minute training session / вечерняя тренировка”, plus a long unit. Create two disposable Templates with the same name for exact-action checks. Pin the timed Activity, run the Sequence to produce a terminal fact for Statistics, and archive disposable Templates.
2. Set the Android zone to America/New_York. In manual History enter 2024-11-03 01:30 for both endpoints. Select UTC−04:00 for the start and UTC−05:00 for the end and navigate to the fact's original date. In Plan try 2027-03-14 02:30 for a gap and 2027-11-07 01:30 for an overlap. If those dates have passed, use the second Sunday in March and first Sunday in November of the next calendar year. Inspect both offsets before choosing one. After saving the History fact, switch Android to a different zone and reopen History. In Statistics select a period spanning the seeded facts. Use 0, 1234.125 (with the locale's accepted input separator) and an omitted value to inspect missing values, grouping, precision and units.
3. Use portrait and landscape on B. Scroll each route/dialog from top to bottom and open the soft keyboard in editors. Check for clipped or overlapping labels, unreadable dates/times/numbers, and actions obscured by the keyboard or navigation bar. Review enabled/disabled, selected, pending and error colors in Light and Dark, with both accents represented. Confirm that text or semantics conveys meaning alongside color. Tab and Shift+Tab with a hardware keyboard, then use Enter on the intended action. Check focus visibility and traversal after dialog close, Back and recreation. Where TalkBack is available, swipe through the actions and confirm labels, roles, state and order.
4. Use the linked state fixtures to reproduce loading, pending, failure and retry. Settings holds a read/write before completion, Archive publishes an explicit restore failure and expanded Sequence gates a refresh. On an ordinary install, inspect visible loading/pending when it occurs and record failure/retry visual checks without a reproducible capture as pending. Record the route, configuration, state, outcome and screenshot or test report.

## Execution record

- Local app JVM verification passed all 651 tests, including the resource contract, appearance, Settings persistence and historical timestamp suites. App Detekt, ktlint and Android lint passed. Both debug APKs assembled.
- The focused production contract test failed after a temporary `%d` → `%s` change in the Russian archive `few` form. It reported `archived_templates_count: EN[other]=[1:d] vs RU[few]=[1:s]`. The production fixture was restored and the contract passed.
- Controller `ci-host` and `gmd-api33-app` are pending. These labels identify the host gate and API 33 app instrumentation suite. AndroidTest APK packaging provides compilation evidence.
- Manual checks and wider API/CI release verification are pending. Cross-route lifecycle, canonical persistence, system scaling, reflow, contrast and focus remain open beyond the individual assertions above.
