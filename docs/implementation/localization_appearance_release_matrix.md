# RU/EN localization and appearance release matrix

S1 verifies the production string contract. S2 adds production theme and scaling assertions for primary interactive routes. S3 adds combined-appearance cases for Plan, History, and Statistics. S4 connects preference changes and Activity recovery to canonical repository reads. AppCompat owns app language. DataStore owns the four appearance preferences. Use the [design guide](../design/README.md) for visual criteria and the [implementation clarifications](../spec/lifetracing_implementation_clarifications.md) for historical timestamps and Plan scheduling.

## Manual protocol

1. Start with an empty disposable installation. In Library create a timed Activity with a Number field, a No-live Activity and a two-step Sequence using those Templates. Use long names and a comment, for example “Tempo 42 — 30 minute training session / вечерняя тренировка”, plus a long unit. Create two disposable Templates with the same name for exact-action checks. Pin the timed Activity, run the Sequence to produce a terminal fact for Statistics, and archive disposable Templates.
2. Set the Android zone to America/New_York. In manual History enter 2024-11-03 01:30 for both endpoints. Select UTC−04:00 for the start and UTC−05:00 for the end and navigate to the fact's original date. In Plan try 2027-03-14 02:30 for a gap and 2027-11-07 01:30 for an overlap. If those dates have passed, use the second Sunday in March and first Sunday in November of the next calendar year. Inspect both offsets before choosing one. After saving the History fact, switch Android to a different zone and reopen History. In Statistics select a period spanning the seeded facts. Use 0, 1234.125 (with the locale's accepted input separator) and an omitted value to inspect missing values, grouping, precision and units.
3. Use portrait and landscape on B. Scroll each route/dialog from top to bottom and open the soft keyboard in editors. Check for clipped or overlapping labels, unreadable dates/times/numbers, and actions obscured by the keyboard or navigation bar. Review enabled/disabled, selected, pending and error colors in Light and Dark, with both accents represented. Confirm that text or semantics conveys meaning alongside color. Tab and Shift+Tab with a hardware keyboard, then use Enter on the intended action. Check focus visibility and traversal after dialog close, Back and recreation. Where TalkBack is available, swipe through the actions and confirm labels, roles, state and order.
4. Use the linked state fixtures to reproduce loading, pending, failure and retry. Settings holds a read/write before completion, Archive publishes an explicit restore failure and expanded Sequence gates a refresh. On an ordinary install, inspect visible loading/pending when it occurs and record failure/retry visual checks without a reproducible capture as pending. Record the route, configuration, state, outcome and screenshot or test report.
5. On an isolated device in C, choose System in LifeTracing. With Android English, check Settings and Back in English while the selected app option stays System. Switch the primary Android language to Russian, return to the app and check both labels in Russian with System still selected. Choose explicit English and then explicit Russian with the opposite device language, and check that the selected option and displayed labels follow the explicit override. On API 33+, verify the app language in Android Settings. Return to System and verify the override clears. Restore the device's starting language after the run.
6. On API 31 and 33, select explicit Russian and configuration B's appearance. In Archive, restore one disposable Template and leave another archived. Record both names and verify the restored row has left Archive. For the ordinary debug installation, verify `adb shell pm path com.alexandr5476.lifetracing.debug` returns an installed package. Leave Archive open and verify `adb shell pidof com.alexandr5476.lifetracing.debug` returns a process ID. Run `adb shell am force-stop com.alexandr5476.lifetracing.debug`, then verify the same `adb shell pidof com.alexandr5476.lifetracing.debug` returns no process ID. Relaunch from the launcher, retaining existing application data. For another variant, determine its installed applicationId and use that same package in all three commands; the productionStartup debug variant uses `.debug.startup`. This verifies a process restart, unlike Activity recreation or a fresh Activity launch in the same process. Open Settings from Daily and check Russian and all four appearance choices. Reopen Archive and Library to confirm one Template remains archived and the other appears in Library exactly once. Verify that Back and the current Restore action remain available. Repeat the restart with System under Android English and Russian, keeping app data between launches.
7. On the physical device in B, change Android font and display size separately with application scales held at 100%/100%, then repeat at 120%/130%. Check that Android's larger settings still increase the effective presentation and that top/bottom actions remain reachable in Settings, Archive, editors, Plan, History and Statistics. In C, toggle Android Light/Dark under System theme, then confirm explicit Light and Dark override the opposite Android mode. Restore the original Android settings when finished.
